# Design-terms audit

Audit of the AiCargo UI (customer orders “Миний захиалгууд”, tracking, admin price/weight tables, forms, modals, bottom nav) against the 20 terms in the reference video. UI-only. No API, schema, auth, payment, loyalty, import, or Bot/ManyChat changes.

Rollback target: `34089835b50bc82cd6347027b1eaf4d0eaedd683` (`origin/main` at the time of this branch).

Screenshots in the pull request are **mocked local fixtures** (`/dev/design-preview`, not shipped). They are not live tenant data and were not taken from a Vercel preview.

| # | Term | Where it matters | Current state before this change | Decision |
| --- | --- | --- | --- | --- |
| 1 | Kerning | Nav wordmark, order titles, Mongolian headings | `font-feature-settings` set `cv11` and `ss01` without `kern`, which can turn kerning off. Inter (Cyrillic UI) and Geologica (brand display) both ship with kerning. | **Fix now.** `font-kerning: normal` and `'kern' 1` on `body`. |
| 2 | Optical centre | 404 / empty full-viewport states, icons | Lucide icons and the logo box are already optically drawn. Full-viewport 404 (`.sys-page`) was geometrically centered, which reads slightly low. | **Fix now** for `.sys-page` only (extra bottom padding). **Skip** nudging modals and play icons: a vertical shift clips short phones, and `PlayCircle` is already balanced. |
| 3 | Tabular numbers | Order prices, tracking codes, admin prices/weights/counts, stat tiles | `.num`, `.ometa`, stat values, and several dates already used `tabular-nums`. Inline admin prices (handover, arrived, report, history groups) and tracking codes did not. | **Fix now** at the root (`font-variant-numeric: tabular-nums` and `'tnum' 1`) so every price, weight, count, phone, date, and code inherits it. Proportional figures are not used in this product UI. |
| 4 | Layout shift | Orders loading, announcement images, logo | Orders `loading.tsx` drew tall cards while the real list is ~60px rows inside one list. Banner images had no reserved box. Nav logos already reserve a box; wide logos remember their ratio. | **Fix now:** skeleton matches chips + rows; banner images get width, height, aspect-ratio, and a surface placeholder. **Skip** rewriting the logo ratio cache. |
| 5 | Tracking | Tracking codes, headings, eyebrows | Body copy had no negative tracking. Tracking codes (`.ocode-text`) used `-0.02em`, which tightens monospace digits. Display headings use a small negative tracking on purpose. Brand `h1` forces `letter-spacing: 0`. | **Fix now** on codes (`.ocode-text`, `.oname-code`, `.sc-code`, `.sr-code` → `0.01em`) so similar digits stay separable. **Already fine** for display headings and brand lockup; those were not loosened. |
| 6 | Optimistic update | Toggles, dismiss, payments, arrivals, imports, loyalty | Staff permission toggles and banner dismiss already update the screen before the request returns. Payments, handover, arrivals, imports, and loyalty points are not reversible from the UI. | **Skip.** No new optimistic write. The remaining server actions are money or cargo state, and this pass does not touch their error handling. |
| 7 | x-height | Order meta, codes, body copy | UI face is Inter with Cyrillic and a large x-height. Brand face (Geologica) is only applied when a tenant sets `data-brand`. Prices under status pills were `0.68rem` (~11px). | **Already fine** as a typeface choice (no font swap, so tenant branding stays). **Fix now:** `.ometa` and `.ocode` raised to `0.75rem` (12px) so prices and codes clear the small-text floor. |
| 8 | Touch target | Bottom nav, order chrome, pager, modal close, icon buttons, form controls | Primary `.btn` was already ≥44px on small screens. Icon buttons (38px), order “more” (32px), pager (32–34px), modal close (28px), and some chips were under 44px. | **Fix now** at `max-width: 640px` via `min-width`/`min-height: 44px` on `.nav-hit`, `.icon-btn`, `.sc-more`, `.orders-del`, `.modal-x`, `.pager`, `.an-tab`, `.seg`, `.hit`, and inputs. Desktop density is unchanged. |
| 9 | Leading | Status sentences, notes, terms, FAQ | `body` line-height is `1.6`, which suits Mongolian Cyrillic. Expanded status (`.sc-status`) was `1.45` and felt tight when the sentence wrapped. | **Fix now:** `.sc-status` and long-form blocks (`.page > p`, notes, FAQ, empty states) use `1.65`. Single-line labels and tab chips stay tight so rows do not grow. |
| 10 | Origin-aware animation | Row “⋯” menu, profile menu, popovers | Sheets already rise from the bottom edge (`an-up`). Menus appeared with no origin. | **Fix now** for `.sc-menu`, `.popover`, and `.menu-pop`: `transform-origin: top right` plus a short opacity/transform transition (`@starting-style`). **Skip** rewriting sheet keyframes; they already come from the edge that opened them. |
| 11 | OKLCH | Tenant accent, night/comfort themes, MGL brand | Colors are hex tokens (`--accent` and `[data-theme]` / `[data-brand="mgl"]`) with contrast notes in the file. `color-mix()` already derives tints. | **Skip.** Converting the palette to `oklch()` can shift a channel in some browsers and would repaint tenant and brand themes. Hex stays the source of truth. |
| 12 | Widow | Headings, order notes, terms, landing lead | Tab labels already use `text-wrap: balance`. Body paragraphs did not. | **Fix now:** `text-wrap: balance` on headings, `text-wrap: pretty` on paragraphs and notes. Unsupported browsers keep the old wrapping. |
| 13 | Safe area | Top nav, admin tab bar, landing sticky CTA, sheets, modals, toasts | `viewport-fit: cover` was set. Top nav, admin tab bar, landing sticky bar, and sheets already padded `safe-area-inset-bottom/top`. Centered modals, the loyalty toast, and landscape side insets did not. | **Fix now** for modal overlays (`.lp-modal-bg`, `.pc-bg`, announcement and delete dialogs), toast top, tab bar and sticky bar horizontal insets, and the profile menu position. |
| 14 | Stagger | Landing steps, order list | Landing steps already use `Stagger` / `StaggerItem`. The order list is a working list, not a marketing sequence. | **Already fine** on the landing page. **Skip** staggering “Миний захиалгууд”: it delays scanning and shifts rows. Stagger now also bails out when reduced motion is on. |
| 15 | Line length | Terms, privacy, notes, FAQ, order prose | `.page` is 600px; orders list is 720px so codes fit. Terms and privacy were hard-capped at 640px (~70+ characters). Mobile width is already under a comfortable measure. | **Fix now:** terms and privacy `max-width: 66ch`. Notes, FAQ, and direct page paragraphs cap at `66ch`. The order list itself stays full width. |
| 16 | Affordance | Order rows, tabs, copy, admin bottom nav | Rows are buttons with a chevron, copy has its own control, tabs look pressed when selected, inputs look like fields. | **Fix now** (small): pressed background on `.orow`, inactive `.ochip`, and admin tabs/sheet items. **Already fine** otherwise; no control was restyled into a new pattern. |
| 17 | Combobox | Track search, phone search, short selects | Search is free text (track code or phone), not a list of options. Short choices use buttons or `<select>`. | **Skip.** A combobox would change keyboard and announcement behavior on forms. Not required for these fields, and it would be a new widget. |
| 18 | Interruptible animation | Menus, landing motion, sheets | CSS transitions can be interrupted. Framer Motion (`Reveal`, `Stagger`, `TiltCard`, `AnimatedNumber`) ignored `prefers-reduced-motion`. `usePrefersReducedMotion` read a ref and never re-rendered. Global CSS already collapses CSS animation duration. | **Fix now:** those motion helpers render static content when reduced motion is on. Menu enter uses a transition (interruptible) instead of a one-shot keyframe. Sheet keyframes stay; closing them unmounts immediately. |
| 19 | Progressive disclosure | Order rows, price calculator, FAQ, handover dates | Order rows hide the 4-step track until tap. The price calculator, FAQ, and handover date groups already collapse. | **Already fine.** **Skip** hiding admin fields behind new disclosure; staff need the full form. |
| 20 | Shared element transition | Order row → detail | Detail opens in place under the row. There is no second route to morph into. The View Transitions API on the App Router is easy to get wrong (flashes, back navigation). | **Skip.** In-place disclosure is the current model. A shared-element route would be a navigation change, not a cheap CSS tweak. |

## What changed

- `app/globals.css` — kerning, tabular figures, code tracking, leading, widows/balance, optical centre on the 404, safe-area insets, 44px targets on small screens, origin-aware menus, pressed states.
- `app/orders/loading.tsx` — skeleton matches the compact list.
- `app/orders/OrdersClient.tsx` — nav, pager, language, and phone-edit hit areas; profile menu origin and safe position; delete dialog safe padding.
- `app/components/motion.tsx` — reduced motion actually turns off reveal, stagger, tilt, and the report count-up. Count-up keeps the final number in the DOM (no flash of 0).
- `app/components/AnnouncementModal.tsx`, `SuperAnnouncementModal.tsx` — reserved image box, 44px close control, safe-area padding.
- `app/components/PriceCalculator.tsx`, `ThemeToggle.tsx` — hit-area classes.
- `app/terms/page.tsx`, `app/privacy/page.tsx` — `66ch` measure.

Per-tenant theming (`[data-theme]`, `[data-brand="mgl"]`) still drives color and the brand display face. Hex tokens were not converted.
